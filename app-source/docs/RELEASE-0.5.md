# v0.5 — Workspace and daily workflow corrections

Implemented: canonical routes and legacy client redirects for static hosting; Settings hub and individual preferences; dedicated meals editor; Food unified search with favorites/recent/frequent; Today in-place nutrition and independent recovery logs; three-day merged reminders and day dismissal; pain symptom flags; recovery read-only history and independent trend data; full supplied Default Template v1.0 prescriptions; editable training days/exercises and immutable plan versions; pending training-day IDs; discard vs rest vs skipped_for_round; pause duration; rest preferences and per-exercise rest; previous working sets; wake lock when supported; schedule batches/weekly/specific/extra/clear; backup validation, restore with pre-restore export, CSV export; About package version.

Old records are retained. New optional fields extend schema 1; old recovery records are projected into independent read models without deleting or rewriting originals. Old count-based cycles initialize a pending view from their previous position; saving a new plan persists explicit IDs. Existing completed and active sessions are snapshots. Explicit reset archives the old session and creates a new one.

Verification: TypeScript and static export; 29 unit tests; browser flows cover legacy redirects, canonical routes at mobile/desktop widths, retained nutrition workflows, settings persistence, plan/session isolation, explicit reset, discard, pause, independent Today entries, backup rejection and restore. Real iOS wake lock/background behaviour still requires device QA.

Not complete: Supabase/auth/entity sync/conflict resolution; formal schema-2 migration and comprehensive import validation; cinematic rigged GLB; recipes with structured ingredients; curriculum content workflow; full cross-cycle/e1RM analytics; all advanced training-day notes/warmup/ordering controls; independent entry history editing UI; native iOS release. Language is explicitly Traditional Chinese only. Region and preferred time format are saved metadata, not complete localization. Safety is user-reported rules, not a validated medical diagnostic engine. Recommendation training changes currently direct users to review/edit a plan; unified automated change previews remain incomplete.
